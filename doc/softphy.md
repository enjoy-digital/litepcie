# Soft PCIe PHY

Status: work in progress, started November 2026. Nothing is hardware-validated yet; the status table
below is updated with each pull request.

## Why

LitePCIe runs on the vendors' hard PCIe IPs (`litepcie/phy/*pciephy.py`): the TLP layer, DMA, MMAP
bridges, MSI and the Linux driver are reusable on any FPGA, but the LTSSM, the 8b/10b Physical Layer,
the Data Link Layer and the Type 0 configuration space are done by the hard IP. FPGAs without a PCIe
hard block, or with too few of them, cannot use LitePCIe today (issues #20, #83, #151, #164, #165).

The soft PHY implements PCIe Gen1/Gen2 (8b/10b) on the FPGA transceivers through LiteICLink, the way
the USB3 PIPE project does for USB 3.0, and presents the same contract as the hard-IP PHYs to the
rest of LitePCIe: `SoftPCIEPHY` is a drop-in `phy` for `LitePCIeEndpoint`, `litepcie_gen` and the
LiteX-Boards targets.

Targets, in order: Artix-7 GTP Gen1 x1 (SQRL Acorn CLE-215+ / LiteX Acorn Baseboard), Gen2 x2, Gen2 x4
(LiteX-M2SDR), then other transceivers (7-Series GTX, UltraScale+ GTH/GTY, ECP5 DCU, Gowin, GateMate).

## Architecture

```
                 LitePCIe core (sys clock domain): endpoint, crossbar, DMA, MMAP, MSI
                       sink/source phy_layout(data_width)   id, max_*_size, msi
  ─────────────────────────────────────────────────────────────────────────────────────── SoftPCIEPHY
   core.py       PHYTXDatapath / PHYRXDatapath (sys -> pcie CDC, width conversion)   CSRs, LTSSM tracer
   tl/           TLP framing (STP/SDP/END/EDB), Type 0 configuration space (PM, MSI, PCIe caps),
                 CfgRd/CfgWr completions, Unsupported Request completions, MSI MemWr generation,
                 BAR0 filtering, byte order adaptation
   dll/          DLLPs (ACK/NAK, InitFC/UpdateFC), LCRC, sequence numbers, retry buffer, flow control
                 credits, DLCMSM
   pipe.py       Physical Layer: lanes + LTSSM -> link Symbol stream (32 bits per lane)
   ltssm.py      Detect, Polling, Configuration, L0, Recovery, Hot Reset, Disabled (upstream and
                 downstream roles)
   lanes.py      striping/destriping, lane-to-lane deskew (COM), per-lane polarity
   datapath.py   per lane: scrambler, SKP Ordered Set insertion, CDC, 8b/10b encoder;
                 8b/10b decoder, COM word aligner, descrambler, SKP Ordered Set removal/elastic buffer
   ordered_sets  TS1/TS2 generators and checkers (Link/Lane numbers, N_FTS, rate, control),
                 SKP, FTS, EIOS
   scrambler.py  G(X) = X^16 + X^5 + X^4 + X^3 + 1, seed FFFFh, COM initialization, SKP hold
   serdes/       lane transceiver adapters on LiteICLink (GTP first), lane clocking, simulation model
  ─────────────────────────────────────────────────────────────────────────────────────── transceivers
```

Clock domains:

- `pcie_pipe`: lane clock, 62.5 MHz at 2.5 GT/s and 125 MHz at 5.0 GT/s (40-bit raw transceiver
  interface, 4 Symbols per lane per cycle), generated by an MMCM on the 100 MHz slot reference clock
  and switched with the negotiated rate. The reference clock also feeds the transceiver PLL so the
  link tracks the host's spread spectrum clocking.
- `pcie_pipe_rxN`: per-lane recovered clock; a fabric elastic buffer (SKP removal) brings each lane
  into `pcie_pipe`, then the lanes are deskewed.
- `pcie_link`: fixed 125 MHz, always running: LTSSM, Data Link Layer, Transaction Layer glue.
- `pcie`: the domain exported to LitePCIe (same 125 MHz clock), held in reset until the Data Link
  Layer is active, like the hard IPs' user reset.

## Conventions

- Lane words: Symbol i is `data[8*i:8*(i+1)]` with `ctrl[i]` set for a K Symbol; Symbol 0 is
  transmitted first (`litepcie/phy/soft/common.py`).
- Scrambling (PCIe Base 4.2.1.3): D Symbols only, the LFSR advances on every Symbol except SKP, is
  initialized after each COM; TS1/TS2 and the Compliance Pattern are not scrambled.
- LCRC (3.5.2.1) and DLLP CRC (3.4.1): bytes in transmission order, bits LSB first, all-ones seed,
  remainder complemented and bit-reversed, first CRC byte in `value[0:8]`. The LCRC equals
  `zlib.crc32(sequence_number + tlp)` sent least significant byte first.
- The TLP stream handed to LitePCIe is declared `endianness="big"` with per-DW byte swapping, like
  the Lattice CertusPro-NX PHY.

## Verification

- `python3 -m pytest -v test/test_soft_*.py`: unit tests against the Python reference models in
  `test/model/soft/` (scrambler keystream, CRC conventions against `zlib.crc32`).
- Later milestones add a two-PHY Verilator simulation (upstream and downstream LTSSM roles, ppm/SSC
  and lane skew), DLL tests with error injection, and hardware bring-up with the LTSSM tracer,
  LiteScope and the root port's `lspci -vv` link status.

## Bring-up notes (to be completed)

- Keep the LTSSM disabled (CSR) until the host has booted, enable it, then
  `echo 1 > /sys/bus/pci/rescan`: configuration read timeouts during POST can hang some hosts.
- Observe the LTSSM history and counters over JTAGBone/UARTBone before looking at traces.
- A link in L0 without Data Link Layer shows as `LnkSta: 2.5GT/s x1` with `DLActive-` on the root
  port.
