# Soft PCIe PHY

Status: work in progress, started November 2026. Gen1 and Gen2 run up to x8 on a Kintex-7 GTX board (see the
hardware results). The status table is updated with each pull request.

## Why

LitePCIe runs on the vendors' hard PCIe IPs (`litepcie/phy/*pciephy.py`): the TLP layer, DMA, MMAP
bridges, MSI and the Linux driver are reusable on any FPGA, but the LTSSM, the 8b/10b Physical Layer,
the Data Link Layer and the Type 0 configuration space are done by the hard IP. FPGAs without a PCIe
hard block, or with too few of them, cannot use LitePCIe today (issues #20, #83, #151, #164, #165).

The soft PHY implements PCIe Gen1/Gen2 (8b/10b) on the FPGA transceivers through LiteICLink, the way
the USB3 PIPE project does for USB 3.0, and presents the same contract as the hard-IP PHYs to the
rest of LitePCIe: `SoftPCIEPHY` is a drop-in `phy` for `LitePCIeEndpoint`, `litepcie_gen` and the
LiteX-Boards targets.

Targets, in order: Artix-7 GTP Gen1 x1 (SQRL Acorn CLE-215+ / LiteX Acorn Baseboard), Gen2 x2, Gen2 x4
(LiteX-M2SDR), then other transceivers (7-Series GTX, UltraScale+ GTH/GTY, ECP5 DCU, Gowin, GateMate).

## Architecture

```
                 LitePCIe core (sys clock domain): endpoint, crossbar, DMA, MMAP, MSI
                       sink/source phy_layout(data_width)   id, max_*_size, msi
  ─────────────────────────────────────────────────────────────────────────────────────── SoftPCIEPHY
   core.py       PHYTXDatapath / PHYRXDatapath (sys -> pcie CDC, width conversion)   CSRs, LTSSM tracer
   tl/           TLP framing (STP/SDP/END/EDB), Type 0 configuration space (PM, MSI, PCIe caps),
                 CfgRd/CfgWr completions, Unsupported Request completions, MSI MemWr generation,
                 BAR0 filtering, byte order adaptation
   dll/          DLLPs (ACK/NAK, InitFC/UpdateFC), LCRC, sequence numbers, retry buffer, flow control
                 credits, DLCMSM
   pipe.py       Physical Layer: lane + LTSSM glue in the lane clock (TX multiplexing of EIOS/TS/
                 packets/Logical Idle, TS/EIOS detection, Logical Idle handshake), Data Link Layer
                 streams and LTSSM in "pcie_link", clock domain crossings
   ltssm.py      Detect, Polling, Configuration, L0, Recovery, Hot Reset, Disabled, 2.5 GT/s x1,
                 upstream and downstream roles (LTSSM_PIPE_INTERFACE, UltraScale state encoding)
   debug.py      bring-up CSRs: LTSSM enable/retrain, state, counters, LTSSM tracer
   lanes.py      striping/destriping, lane-to-lane deskew (COM), per-lane polarity
   datapath.py   per lane: Logical Idle filling, SKP Ordered Set insertion, scrambler (TX, lane clock);
                 8b/10b error substitution, descrambler, SKP Ordered Set removal, elastic buffer to
                 the lane clock (RX, recovered clock)
   ordered_sets  TS1/TS2 generator (word aligned) and checker (any Symbol position, fields,
                 inverted polarity), 4-Symbol Ordered Set detector (FTS, EIOS, SKP)
   scrambler.py  G(X) = X^16 + X^5 + X^4 + X^3 + 1, seed FFFFh, COM initialization, SKP hold,
                 automatic Training Sequence bypass
   coding.py     8b/10b code tables and RX checker (decode/disparity errors)
   serdes/       lane contract (base), Artix-7 clocking, GTP adapter on LiteICLink, simulation model
  ─────────────────────────────────────────────────────────────────────────────────────── transceivers
```

Clock domains:

- `pcie_pipe`: lane clock, 62.5 MHz at 2.5 GT/s and 125 MHz at 5.0 GT/s (40-bit raw transceiver
  interface, 4 Symbols per lane per cycle), generated by an MMCM on the 100 MHz slot reference clock
  and switched with the negotiated rate. The reference clock also feeds the transceiver PLL so the
  link tracks the host's spread spectrum clocking.
- `pcie_pipe_rxN`: per-lane recovered clock; a fabric elastic buffer (SKP removal) brings each lane
  into `pcie_pipe`, then the lanes are deskewed.
- `pcie_link`: fixed 125 MHz, always running: LTSSM, Data Link Layer, Transaction Layer glue.
- `pcie`: the domain exported to LitePCIe (same 125 MHz clock), held in reset until the Data Link
  Layer is active, like the hard IPs' user reset.

## Conventions

- Lane words: Symbol i is `data[8*i:8*(i+1)]` with `ctrl[i]` set for a K Symbol; Symbol 0 is
  transmitted first (`litepcie/phy/soft/common.py`).
- Scrambling (PCIe Base 4.2.1.3): D Symbols only, the LFSR advances on every Symbol except SKP, is
  initialized after each COM; TS1/TS2 and the Compliance Pattern are not scrambled. They are the
  only Ordered Sets with a D Symbol or PAD right after the COM, so the scrambler and descrambler
  bypass that Symbol and the 14 following ones by themselves: the descrambled RX stream carries the
  Training Sequences with readable fields and no side channel is needed.
- RX word phase: the transmitter builds its stream in 4-Symbol units (TS, Ordered Sets and framed
  packets are all multiples of 4 Symbols) but the receiver's word phase is arbitrary. There is no
  word aligner on COM: SKP Ordered Sets are removed whole (4 Symbols, phase preserved) in the
  recovered clock domain, Training Sequences and Ordered Sets are detected at any Symbol position,
  and the packet framing (Data Link Layer) realigns on STP/SDP only, where dropping idle Symbols
  is harmless. Realigning on every COM would drop packet Symbols around SKP Ordered Sets.
- Clock compensation: one SKP Ordered Set every 352 words (1408 Symbols) between packets/Ordered
  Sets; on RX the elastic buffer is the recovered-to-lane clock FIFO after SKP removal, words are
  dropped (counted) if it overflows.
- LTSSM (4.2.6): the LTSSM runs in the fixed "pcie_link" clock and only sees events: Training
  Sequences received with their fields (one AsyncFIFO entry per TS), TS transmitted, Logical Idle
  handshake done, Electrical Idle, receiver detection. The consecutive/transmitted counters restart
  on every state change and the state conditions see them cleared on the first cycle of a state.
  Polling.Compliance and Loopback are not entered (back to Detect), L0s/L1 and the speed change
  come with later milestones. The state encoding is the Xilinx UltraScale one (L0 = 0x10), so the
  existing LTSSM tracer decoding applies.
- LCRC (3.5.2.1) and DLLP CRC (3.4.1): bytes in transmission order, bits LSB first, all-ones seed,
  remainder complemented and bit-reversed, first CRC byte in `value[0:8]`. The LCRC equals
  `zlib.crc32(sequence_number + tlp)` sent least significant byte first.
- The TLP stream handed to LitePCIe is declared `endianness="big"` with per-DW byte swapping, like
  the Lattice CertusPro-NX PHY.

## Verification

- `python3 -m pytest -v test/test_soft_*.py`: unit tests against the Python reference models in
  `test/model/soft/` (scrambler keystream, CRC conventions against `zlib.crc32`), lane datapath
  round trips between two clock domains (SKP compensation), Training Sequence generator/checker at
  every Symbol position, two serdes models back-to-back (`serdes/model.py`), GTP adapter
  elaboration to Verilog.
- `python3 bench/soft/sim_soc.py [--mps 256] [--dma-size 1024] [--dma-buffers 4]`: SoC as the Acorn target
  (`add_pcie`, 64-bit DMA) against a host model with the Linux driver's register sequence: CSRs over
  BAR0, DMA tables, loopback through host memory with Completions split at 64 bytes, MSIs, buffers compared.
- `python3 bench/soft/sim_endpoint.py [--data-width 64|128]`: a scripted root (soft Physical and Data
  Link Layers, downstream role) against a LitePCIe endpoint on `SoftPCIEPHY`, wire TLPs compared.
- `python3 bench/soft/sim.py --timer-scale 100` (or `--timer-scale 1` for the specification
  timers): Verilator simulation of an upstream and a downstream Physical Layer through two serdes
  models: LTSSM states displayed, L0, packets both ways checked, Link Retrain (Recovery), "SIM OK".
  `python3 -m pytest -m slow test/test_soft_sim.py` runs it (needs Verilator). The Migen simulator
  is far too slow for the full link (about 15 cycles per second), so the Migen tests stop at the
  LTSSM pair (`test/test_soft_ltssm.py`, behavioral link) and the elaboration of the Physical
  Layer.
- `bench/soft/sim.py --with-dll [--corrupt-every N] [--drop-dllp-every N] [--debug]`: the same
  link with the Data Link Layers: flow control initialization, DL_Active, TLPs both ways checked,
  replays and receiver errors reported.
- Later milestones add ppm/SSC and lane skew in the Verilator simulation, and the hardware bring-up with the LTSSM tracer, LiteScope and the root port's
  `lspci -vv` link status.

  constrained to 7.5 ns (133 MHz), about 0.5 ns of margin at 125 MHz.
- The soft PHY has half the line rate of the hard IP here until the Gen2 milestone.

## Options and power management

`SoftPCIEPHY` alone has only the CSRs of the PHY contract, and its LTSSM starts on its own. Two optional
additions, for bring-up (`--with-debug`, `--with-ltssm-tracer` on `bench/soft/acorn.py --with-endpoint`):

- `add_debug(enable_reset=0)`: LTSSM enable/retrain and status, counters. The LTSSM then waits for the
  enable CSR.
- `add_ltssm_tracer()`: LTSSM state history, as with the hard-IP PHYs.

No Link Power Management is implemented: no L0s, L1, L2 or ASPM, and no PM DLLP is generated or acted on.
Link Capabilities advertises no ASPM, Link Control's ASPM Control and Device Control's Aux Power PM are
hardwired to 0, and the N_FTS in Training Sequences is a fixed value (the partner's is ignored). What
remains is required: the PM capability (mandatory for a PCIe function, D0/D3hot PowerState only, no
PME), EIOS and Electrical Idle detection (Recovery and link down, not low power states). The
`RXLPM_*` transceiver attributes are unrelated: LPM is the GTP's only receive equalizer.

Known limitations of the Transaction Layer glue: no MSI-X, no BAR/Memory Space Enable decoding
(LitePCIe masks the address), no PME_TO_Ack (a host waiting for it at shutdown times out), and an
NP-starved request blocks the TLPs behind it (single transmit queue). The DLL timers are fixed
values not yet checked against the specification tables. Receiver detection is stubbed (always
present), Electrical Idle comes from the GTP detector.

## Bring-up on the YPCB-00338-1P1

`bench/soft/ypcb.py` over JTAGBone, `bench/soft/status.py` for the control and status:

```sh
python3 bench/soft/ypcb.py --with-endpoint --driver --build     # --hard-ip for the same design on the hard IP.
litex_server --jtag --jtag-config openocd_xc7_ft232.cfg
python3 bench/soft/status.py --csr-csv build/soft_ypcb/csr.csv enable status trace
echo 1 > /sys/bus/pci/devices/<root port>/remove                # Once dl_active is set.
echo 1 > /sys/bus/pci/rescan
```

`--speed gen2` advertises 5.0 GT/s: the link trains at 2.5 GT/s, then the root port changes the speed (with Link Control 2
and Retrain Link if it doesn't do it on its own, or `status.py speed` from the device).

The LTSSM is disabled at reset and by PERST#, so that a design making a host hang cannot do it again at the next boot.

Remove the root port before the rescan when the BIOS saw no device at boot. A rescan alone assigned the memory window
without programming it on the host tested: the kernel log and `lspci` show the window, the root port's configuration
offset 0x20 still reads `0000fff0`, and BAR reads return all-ones.

Check the device ID and the build date after each reboot: a warm reboot usually keeps the design, but one reloaded the
FPGA from its flash.

`--nlanes` selects the width (x2 on the first lanes of the x4 pins), with LitePCIe at 32 bits per lane.

## Multi-lane links

The width is negotiated in Configuration: each lane answers with the Link and Lane Numbers it receives, the width is
the largest of x1, x2, x4, x8 with these lanes from Lane 0, the others go to Electrical Idle. The Data Link Layer keeps
the width of the design, the Physical Layer splits its beats into words for the lanes in use and makes beats from
their words, aligning the packets on a DW first at x1 and x2. Lane reversal isn't handled.

Above x1 the Data Link Layer works on beats of a DW per lane (`dll/wide.py`), at 125 MHz whatever the width:

- RX: the K Symbols are only found at the packets' boundaries, so the DW slots of a beat are classified in
  parallel. Packets start on a DW from x4 on; at x2 they can also start 2 Symbols into a DW, `RXPhaseAligner`
  realigns them by inserting or deleting a Symbol time of Logical Idle. A beat can hold the end of a TLP and the
  start of the next one: a FIFO and `TLPRepacker` make first-aligned beats. A TLP of `4*k+1` DWs takes more output
  beats than input ones, the FIFO absorbs that during a burst; if it fills up the TLPs are Naked.
- TX: one packet per beat, the end of the beat in Logical Idle, PAD above x4.
- `lanes.py`: Ordered Sets at the same time on all the lanes, striping, per-lane polarity, deskew on the COM Symbols
  of the Training Sequences (16 words per lane).

The LTSSM follows Lane 0, it waits for the lanes to be deskewed for 8 Training Sequences before leaving Polling.Active
and Recovery.RcvrLock. COMs arriving together can be of different Training Sequences when receivers restart at
different times with old words in a FIFO, so the distance between the lanes is checked on every COM.

At 5.0 GT/s the receiver has to tolerate 8 ns between the lanes. The transmitters' buffers are on, so their
latency isn't matched between lanes: the host's receivers have accepted it up to x8, it wasn't measured.

## Bring-up on the Acorn (M2.5/M3)

`--with-endpoint` builds the full endpoint (SoftPCIEPHY, LitePCIe MMAP, DMA, MSI, `--driver` for the
kernel driver); add `--with-debug --with-ltssm-tracer` for bring-up (CSRs `pcie_endpoint_phy_debug_*` and
`pcie_endpoint_phy_ltssm_tracer_*`, steps below). Once L0 and DL_Active are reached, Linux should enumerate
it as a `10ee:7021` device.


`bench/soft/acorn.py --build [--load] [--with-jtagbone] [--with-analyzer]` builds the soft
Physical Layer alone (no Data Link Layer yet) on the SQRL Acorn CLE-215(+) / LiteX Acorn Baseboard
in a PC slot, with UARTBone (default) or JTAGBone and the `pcie_phy` debug CSRs:

1. Boot the host with the LTSSM disabled (`pcie_phy_control.enable = 0` at reset): configuration
   read timeouts during POST can hang some hosts.
2. `litex_server --uart ...` (or `--jtag`), check `pcie_phy_status.serdes_ready`, then
   `pcie_phy_control.enable = 1` and `echo 1 > /sys/bus/pci/rescan` on the host.
3. Read the LTSSM history (`bench/test_ltssm_tracer.py`, UltraScale table), `pcie_phy_status`
   (`ltssm`, `l0`, `link`, `lane`, `rx_polarity`) and the counters: Training Sequences received and
   corrupted, 8b/10b errors, elastic buffer overflows, DLLP/TLP starts received in L0 (the host's
   InitFC DLLPs are the proof of L0 at the Data Link Layer).
4. On the host, the root port shows `LnkSta: 2.5GT/s x1` with `DLActive-` while in L0.
5. `--with-analyzer`: LiteScope on the lane Symbols (RX/TX), TS detection and the LTSSM state in
   the lane clock domain (`analyzer.csv`).
